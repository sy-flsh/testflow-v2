# TestFlow v2 — Release Notes `v0.1.0-rc.2`

> Status: Release Candidate · 내부 검증용 빌드
> Stack: Next.js 15 (App Router) · React 19 · Prisma 7 · PostgreSQL

이번 릴리즈는 TestFlow v2의 핵심 QA 워크플로(Project → TestCase → TestRun → Defect → Dashboard/Report)와
인증·권한·운영 안정성 기반을 갖춘 첫 번째 기능 완결형 후보 빌드입니다.

---

## 1. 주요 기능

핵심 도메인의 DB 스키마 / API / 화면이 end-to-end로 연결되었습니다.

- **Project**: 워크스페이스 단위의 프로젝트 생성·조회·관리.
- **TestCase / TestFolder**: 폴더 기반 테스트케이스 관리, 단계(TestStep) 구성, 일괄(bulk) 작업.
  - **CSV Import**: `preview → commit` 2단계 임포트.
  - **XLSX Template**: 표준 템플릿 다운로드(`template.xlsx`).
  - **AI Draft**: AI 기반 테스트케이스 초안 생성 및 저장.
- **TestRun / TestRunResult**: 테스트 실행 생성, 결과 기록, 결과 단위 처리 및 bulk 결과 업데이트.
- **Defect / DefectLink**: 결함 등록·관리 및 테스트 결과와의 연결.
- **Dashboard**: 워크스페이스 단위 요약 지표(`/api/dashboard/summary`).
- **Report**: 프로젝트 단위 리포트 요약(`/api/projects/[projectId]/reports/summary`).
- **Settings / Workspace Members**: 워크스페이스 및 멤버 관리.

데이터 모델: `User`, `Workspace`, `WorkspaceMember`, `Project`, `TestFolder`, `TestCase`, `TestStep`,
`TestRun`, `TestRunResult`, `Defect`, `DefectLink`, `AiTestCaseDraft`, `Session`, `RateLimitBucket`.

---

## 2. 인증 / 권한

- **인증 방식**: 커스텀 credentials 로그인 + DB 백업 opaque 세션 쿠키.
  - 쿠키명 `tf_session`, 세션 기간 14일.
  - 쿠키 옵션: `HttpOnly`, `SameSite=Lax`, 운영 환경에서만 `Secure`, `Path=/`.
  - 원본 토큰은 DB에 저장하지 않고 `Session.tokenHash`만 저장.
- **세션 컨텍스트**: `/api/auth/me`가 현재 사용자·워크스페이스·역할·권한·워크스페이스 목록 반환.
  `AuthProvider`로 앱 페이지의 인증 상태를 중앙화하여 중복 호출 감소.
- **페이지 보호**: `middleware.ts`가 미인증 사용자를 `/login?next=<현재경로>`로 리다이렉트.
  `next`는 내부 경로만 허용하고 외부 URL은 거부.
- **API 가드 적용 범위**: Workspace, Projects, Dashboard, Project Report,
  TestCase/TestFolder, CSV Import/XLSX Template/AI Draft, TestRun/TestRunResult, Defect/DefectLink.

**RBAC 정책**

| Role | Read | Create | Update | Delete | Danger Zone |
| --- | --- | --- | --- | --- | --- |
| Admin | Yes | Yes | Yes | Yes | Yes |
| Member | Yes | Yes | Yes | No | No |
| Viewer | Yes | No | No | No | No |

> UI는 동일한 권한을 반영해 제한된 액션을 숨기거나 비활성화하지만, **최종 enforcement는 API 가드**가 담당합니다.

---

## 3. 보안 / 운영 안정성

- **CSRF 가드**: 모든 unsafe 메서드(`POST`/`PUT`/`PATCH`/`DELETE`)에 same-origin 검증.
  `Origin` 헤더 우선, 없을 경우 `Referer` fallback.
- **Rate Limit** (DB 백업 `RateLimitBucket`):
  - 로그인 IP 시도: 10회 / 10분
  - 로그인 이메일 실패: 5회 / 10분
  - 회원가입 IP 시도: 5회 / 10분
  - AI Draft 생성: 사용자당 20회 / 1시간
  - CSV Import preview/commit: 사용자당 30회 / 1시간
  - 초과 시 `429 RATE_LIMITED`, 로그인 성공 시 해당 이메일 실패 버킷 리셋.
- **운영용 정리(cleanup)**: `auth:cleanup`으로 만료된 `Session` / `RateLimitBucket`만 삭제.
  활성 세션·버킷은 건드리지 않아 운영 환경에서도 안전(스케줄/크론 권장).
- **개발 DB 리셋 가드**: `db:reset:dev`는 `NODE_ENV=production`,
  비-localhost host, 비-`5433` port에서 실행 차단.

## 4. 테스트 / 검증

- **Auth/Permission Smoke Test** (`npm run test:auth`, alias `test:smoke`):
  로컬 Next.js dev 서버(`127.0.0.1:3210`)를 띄워 다음을 검증.
  - 미인증 페이지 → `/login?next=...` 리다이렉트
  - 미인증 보호 API → `401`
  - Admin 로그인 및 쓰기 권한
  - Member 생성/수정 허용, 삭제 거부
  - Viewer 읽기 허용, 쓰기 거부
  - Dashboard/Report 보호 API 접근
  - 로그아웃 후 세션 무효화
- 이미 떠 있는 서버 대상 실행 지원:
  `TESTFLOW_EXTERNAL_SERVER=1 TESTFLOW_BASE_URL=... npm run test:auth`

## 5. 남은 제한사항

이번 RC는 완전한 production hardening 단계가 아니며, 아래 항목이 남아 있습니다.

- 현재 Origin/Referer 가드를 넘어서는 **CSRF 토큰 강화** 미적용.
- auth / AI Draft / CSV Import 외 **일반 쓰기 API에 대한 rate limit** 미적용.
- **스케줄링된 auth cleanup 잡 및 세션 로테이션 정책** 미구성.
- 권한 버튼·브라우저 플로우에 대한 **Playwright UI E2E** 미구축.
- **`npm audit` moderate 7건** 검토 미완료 (high 0건).

## 7. 검증 명령어

```bash
# 의존성 설치
npm install

# 개발 DB를 seed 기준으로 초기화 (개발 환경 전용)
npm run db:reset:dev

# Auth / Permission Smoke Test
npm run test:auth          # alias: npm run test:smoke

# 외부 서버 대상 검증
TESTFLOW_EXTERNAL_SERVER=1 TESTFLOW_BASE_URL=http://localhost:3000 npm run test:auth

# 만료 세션/레이트리밋 정리 (dry-run 후 실제 실행)
npm run auth:cleanup -- --dry-run
npm run auth:cleanup

# 빌드 / 정적 검증
npm run lint
npm run build
npm run prisma:validate

# 보안 점검 (현재 high 0, moderate 7)
npm audit
```
